# Lab: Map a Familiar Application

Goal: identify the major parts of an application without reading code.
Expected output: a labeled request-and-response diagram.
Prerequisites: none
Tools: paper or a diagram editor

## Step-by-Step Tasks

1. Choose a familiar application action, such as sending a chat message.
2. Mark the user input and visible interface.
3. Draw the request leaving the interface.
4. Add processing and any stored data.
5. Draw the response returning to the interface.
6. Mark one possible failure at each boundary.

## Success Criteria

The diagram has a clear direction, names at least four components, and distinguishes processing from storage.

## Common Errors

Combining all hidden components into one box or drawing data flow with no direction.

## Debugging Guide

Start again from the user's click and ask what must happen before the next visible change.

## Stretch Goal

Add where an LLM could participate and what information it would need.
