# Pedagogy Reference

## Non-Technical Teaching Pattern

1. Name the problem in learner language.
2. Show the system with a concrete analogy or diagram.
3. Connect each block to an observable action.
4. Demonstrate the smallest working example.
5. Let students change one variable at a time.
6. Ask for an explanation, not only a successful run.

## Lesson Shape

Use: hook, mental model, guided demo, hands-on lab, misconception check, reflection, and bridge to the next lesson.

Avoid unexplained jargon, large setup tasks, and theory that does not unblock the next build.

## Assessment

Assess architecture explanations, debugging choices, data flow, and tradeoffs. Syntax recall is secondary unless it is an explicit course outcome.
