# Tool Selection Reference

Score candidate tools against the teaching objective, not popularity alone:

- educational value;
- technical relevance;
- abstraction level;
- stability and maintenance;
- learning curve and setup complexity;
- cost and student access;
- vendor lock-in;
- longevity and alternatives;
- fit with the capstone.

Map each tool to one role: design knowledge, design generation, full-app abstraction, coding agent, backend service, model provider, storage, retrieval, or orchestration. If two tools serve different roles, do not compare them as substitutes.

Choose one primary path for the core course. Keep alternatives as optional comparison material unless they teach a distinct concept.
